# Examples

Two suites, each for a live stand. CI does not run them: there are no devices on CI, and what CI proves is the stub-based `tests/e2e.rs`, which runs a real `bddkit` against a fake Appium server. Build the plugin first with `cargo build --release` from the repository root, then give each suite a lock file pointing at the library (see the root `README.md`, *Installing*).

`android/` drives Appium's public ApiDemos app. It needs Appium 2 or 3 with the `uiautomator2` driver and one emulator or device; Appium downloads the APK from the URL in `bddkit.yaml` itself. Add `examples/android/.bddkit/plugins.local.yaml` (gitignored) with an entry `name: appium`, `path: ../../../target/release/libbddkit_appium.so` (relative to the lock file's own directory), then run `cd examples/android && APPIUM_URL=http://<appium-host>:4723 bddkit run`.

`windows/` drives Calculator. It needs Appium 2 or 3 with the `windows` driver and WinAppDriver on the Windows machine itself, with Developer Mode on. The suite can run from any machine that reaches the Windows Appium: add `examples/windows/.bddkit/plugins.local.yaml` (gitignored) with `name: appium` and `path:` set to the plugin library for YOUR machine (`.so` on Linux, `.dylib` on macOS, `.dll` on Windows), relative to the lock file's own directory, then run `APPIUM_URL=http://<windows-host>:4723 bddkit run` — or on the Windows machine itself with the `.dll` and the default `APPIUM_URL`, just `bddkit run`. Open port 4723 only to the machine running the suite. `I type` types through the Windows machine's active input language; make English the default input method on the Windows machine (Settings → Time & Language → Language → Keyboard → "Override for default input method") during a run (on a Russian layout "hello" arrives as "руддщ"), and nothing else may take focus while a suite runs. The Calculator's automation ids and its `Display is N` text are those of current Windows 10/11 builds and may differ on yours: run `I dump the screen` inside `I am in debug mode` (with `concurrency: 1`) to see what your build calls things and where the files were written.

Between them the two suites use all ten steps.
